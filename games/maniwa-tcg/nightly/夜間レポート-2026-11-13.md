## 5. 姫神戦記（待ち行列9）— 早送り中の印

### 5.1 ★ 理由にしてきたことを、初めて測った

9.5.4 / 9.6.3 / 9.9.5 / 9.16.3 / 9.17.4 は、動きを減らす設定の節で
**「変わった瞬間は早送りで流れてしまう」**を理由に挙げてきた。
**その早送り中に印がどう見えているかは、一度も測っていなかった。**

本物の画面で対戦し、`requestAnimationFrame` ごとに一過性クラスの有無を見て
**DOM に居た時間**を数えた（早送りオフ/オンで各60秒）。

### 5.2 結果：早送り中の滞在は **49〜117ms**。山に届くものは1つも無い

CPU の1手は `main.ts` で **550ms → 60ms** になる。

| クラス | オフ | **オン** | 動きの山 |
|---|---|---|---|
| `turn--new` | 355ms（65%） | **55ms（10%）** | — |
| `banner__lp--down` | 480ms | **97ms（24%）** | 160ms |
| `pile__count--up` | 642ms | **106ms（27%）** | 160ms |
| `pile__count--down` | 551ms | **51ms（13%）** | 160ms |
| `card--strike-down` | 463ms | **74ms（22%）** | 153ms |
| `card--atk-up` | **83ms（20%）** | **49ms（12%）** | 126ms |
| `card--atk-down` | 550ms | **50ms（12%）** | 126ms |

> **★ 早送りオフでも `card--atk-up` は 83ms しか居ない。**
> 攻撃力が変わった直後にもう1手進むと、その描き直しで印が消える。
> **早送りだけの問題ではない。**

### 5.3 直したもの

`renderDuel` が `vm.fast` のとき根に `is-fast` を付け、CSS がそれを見る。
**足したのは、動きを減らす設定で「代わりを置く」と決めた3つだけ**
（`card--drawn` / `card--atk-up` / `card--atk-down` / `card--openable`）。

**ライフ・山墓の数・ターン番号・攻撃の縁には足していない。**
9.5.4 / 9.6.3 / 9.9.5 / 9.17.4 が「数字や縁が残るので代わりは要らない」と決めており、
**早送りでも数字と縁は残る。決めたことを早送りだけで覆さない。**

印の値は `:root` の `--mark-*` に**1か所だけ**置き、動きを減らす設定の節と
早送りの節が同じ変数を読む。**既存の節は値を変数参照に置き換えただけ**で、
出る印は1ピクセルも変えていない（計測で確認）。

### 5.4 直したあとの実測

| | 早送りオフ | 早送りオン |
|---|---|---|
| `card--drawn` の outline | `none` | **`solid`** |
| `card--atk-up` の box-shadow | `none` | **`rgb(245,240,225)` の inset** |
| `card--openable` の box-shadow | 透明（動きの0%） | **`rgba(245,240,225,0.85)`** |

写真は `shots-2026-11-13/` に2枚（早送りオン / オフ）。

### 5.5 残したもの

- **早送りの速さ（60ms）は変えていない。** SPEC 8.1 の取り決めなので提案に留める
- **オフでも 83ms しか居ない `card--atk-up`** は、早送りとは別の原因
  （次の手の描き直しで消える）なので今夜は触っていない。**判断に足す**
