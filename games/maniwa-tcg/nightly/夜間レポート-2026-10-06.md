#### (3) 決着の姫神を、締めとして遅れて立ち上げる【SPEC 9.4.19・新しい演出】

`.finalArt__art` の `animation-name` は **`none`** だった。画面全体に `screenIn`
（0.18秒）が1つ当たっているだけで、**決着の姫神が通算の行やボタンと同時に出ていた。**
9.8.1 はここを「対戦の締め」と位置づけているのに、それが画面に現れていない。

タイトル画面が同じことを既にやっている（9.4.2）ので、**同じ考え方を当てただけ**で
新しい語彙は増やしていない。

| | 値 | 実測（計算後のスタイル） |
|---|---|---|
| 名前 | `finalArtRise` | `animationName: "finalArtRise"` |
| 長さ | 0.42秒 | `animationDuration: "0.42s"` |
| 遅れ | 0.16秒 | `animationDelay: "0.16s"` |
| プロパティ | `transform` と `opacity` のみ | — |

**取り合いは起きない。** この要素は `animation` を持っていなかった（上の `none`）。
`border` と `box-shadow` はこの要素が通常時から持っているので触っていない。

**動かさない端末（`prefers-reduced-motion: reduce`）**:

```
{"finalArt_animationName":"none","finalArt_outlineStyle":"solid",
 "finalArt_outlineWidth":"2px","finalArt_outlineColor":"rgb(245, 240, 225)"}
```

「動かさない代わりに何も出さない」にはしていない。この演出が伝えているのは
**「この絵が締めの主役である」**ことなので、`outline` で枠を出す。
`box-shadow` を使わないのは、この要素が通常時から持っていて、割り込むと
**動かさない端末だけ見た目が変わってしまう**ためである
（2026-10-04 に `box-shadow` で同じ失敗をして `outline` に書き直した）。

証拠: `shots-2026-10-06/fx-finalArt-normal.png` / `fx-finalArt-reduce.png`

#### (4) 通算の二重計上を直す【SPEC 9.8.4・計測の副作用で見つけた不具合】

`showResult` の先頭で `recordResult` を呼び、下の音ボタンが
`soundToggle(showResult)` で**同じ関数を呼び直していた**。

**直す前（実測）**: 音ボタンを**1回**押しただけで

```
通算 0勝 1敗 0分   →   通算 0勝 2敗 0分
```

**直したあと（実測・音ボタンを3回押した）**:

```
["通算 0勝 1敗 0分","通算 0勝 1敗 0分","通算 0勝 1敗 0分","通算 0勝 1敗 0分"]
```

数えるのと描くのを分けた（`showResult` が数えて `renderResult` が描く）。
**この画面に限った話ではない**ので、「保存の書き換えは画面を描く関数の外に出す」
として SPEC 9.8.4 に書いた。

  くぐらされるほうは**攻撃してきた者を守備に伏せる**形で残した
- **a026**: 「逆らうことも隠れることもできない」。伏せて・削って・落とす、
