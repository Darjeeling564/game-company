#### (1) 演出どうしの取り合いをほどく（SPEC 9.4.13・新規）

**09-22 に見つけた `.card--hit` と `.card--drained` の競合を、測ってから直した。**

まず同じカードに乗りうる10クラスを総当たりで当て、計算後の `animation-name` を見た。
**29組で片方が消えていた。** ただしこれは「起こりうる」組であって「起きている」組ではない。
そこで本番と同じ `renderBattle` を呼び、**120試合・6378回の描き直し**を走査して
実際に同時に乗った組を数えた。

| 実際に同時に乗った組 | 件数 | 消えていたか |
|---|---|---|
| `card--hit` + `card--weak` | 146 | いいえ（弱点は `::before`） |
| `card--hit` + `card--lunge` | 105 | **はい。`cardHit` が消えていた** |
| `card--hit` + `card--drained` | 85 | **はい。`cardHit` が消えていた** |
| `card--hit` + `card--envenom` | 70 | いいえ（毒は `::after`） |
| `card--hit` + `card--ultimate` | 45 | **はい。`cardHit` が消えていた** |
| `card--drained` + `card--swap-out` | 44 | **はい。`cardDrain` が消えていた** |
| `card--drained` + `card--weak` | 10 | いいえ |
| `card--envenom` + `card--weak` | 3 | いいえ |

**消えていた4組はすべて、被害を受けた側の合図が消える向きだった。**
残るのは「自分が何をしたか」（踏み込み・一回転・入れ替え）で、
消えるのは「自分に何が起きたか」（被弾の揺れ・剥がしの光）。**順序が逆である。**

直し方は**動かすプロパティで分ける**こと。`animation` はカンマで並べれば同時に走る。

| 演出 | 動かすもの |
|---|---|
| `cardHit` | `transform` / `filter` |
| `cardDrain` | `box-shadow` **のみ** |
| `swapInUp` / `swapOutDown` | `transform` / `opacity` |
| `lungeUp` / `lungeDown` | `transform` |
| `cardUltimate` | `transform` / `filter` |

**既存の規則は1つも書き換えていない。** 2つのクラスを並べた詳細度の高い規則を足しただけ。

```css
.card--hit.card--drained { animation: cardDrain 0.5s ease-out, cardHit 0.42s ease-out; }
.side--human .card--drained.card--swap-out { animation: cardDrain 0.5s ease-out, swapOutDown 0.36s ease-out both; }
.side--human .card--hit.card--lunge { animation: cardHit 0.42s ease-out, lungeUp 0.34s cubic-bezier(0.3, 0, 0.3, 1); }
```

結果（計算後の `animation-name` を両側で実測）。

| 組 | 側 | 直す前 | 直したあと |
|---|---|---|---|
| hit + drained | 共通 | `cardDrain` のみ | **`cardDrain, cardHit`** |
| drained + swap-in | human / cpu | `swapInUp` / `swapInDown` のみ | **`cardDrain, swapInUp` / `cardDrain, swapInDown`** |
| drained + swap-out | human / cpu | `swapOutDown` / `swapOutUp` のみ | **`cardDrain, swapOutDown` / `cardDrain, swapOutUp`** |
| hit + lunge | human / cpu | `lungeUp` / `lungeDown` のみ | **`cardHit, lungeUp` / `cardHit, lungeDown`** |
| hit + ultimate | 共通 | `cardUltimate` のみ | **`cardUltimate` のまま（後述）** |

- **hit + drained / drained + swap-\*** は動かすプロパティが重ならないので**完全に両立**した
- **hit + lunge** は `transform` が重なる。踏み込みを勝たせ、**被弾の `filter`（白く飛ぶ）だけを
  取り戻した**。揺れは戻らないが「殴られた」ことが色で残る
- **hit + ultimate** は `transform` も `filter` も重なるため、**カンマでは取り戻せない**。
  直していない（10. に提案として書く）

**実際に画面に出ることを確かめた。** 200試合まで回して `.card--hit.card--drained` が
乗った瞬間を捕まえ、`animation-play-state: paused` と負の `animation-delay` で
150ms の位置に止めて撮った（[`fix-hit-drained.png`](shots-2026-09-24/fix-hit-drained.png)）。
その瞬間の計算後スタイルは次のとおりで、**3つの演出が同時に生きている**。

```
クラス     card card--board card--active card--hit card--drained card--weak card--wounded
animation  cardDrain, cardHit
filter     brightness(1.39)                       ← cardHit
box-shadow rgba(198,210,218,0.89) 0 0 14.5px 5.8px ← cardDrain
transform  matrix3d(0.981847, 0, 0.189676, ...)   ← cardHit
```

`prefers-reduced-motion: reduce` のブロックにも、足した4つの組み合わせクラスを入れた。

#### (2) 「エネルギーの在庫なし」の丸が読めない（SPEC 9.4.14・新規）

計測で出た唯一のコントラスト違反。**`.energy__orb--none` だけが半透明のクリーム**
（`rgba(245,240,225,0.22)`）で、盤の森緑と合成すると **rgb(89,123,97)** になる。
そこに `#10180f`（ほぼ黒）の「—」が載っていて **3.3:1**（下限 4.5:1）だった。

**文字色をどう変えても届かない。** この背景（輝度 0.172）で 4.5:1 を満たす文字色は
白より明るいか黒より暗いかのどちらかで、存在しない。**丸のほうを変えるしかない。**

同じ問題は `.energy--used` がすでに解いていた（背景を 0.18 に落とし、文字をクリームに
反転して 4.56:1）。**`--none` も同じ形にそろえた。**「置くものが無い」状態なので、
明るくして目を引かせるより沈めるほうが筋が通る。`--used` とはグリフ（「—」と「✓」）と
行全体の `opacity` で区別できる。

| | 丸 | 合成後の背景 | 文字 | 比 |
|---|---|---|---|---|
| 直す前 | `rgba(245,240,225,0.22)` | rgb(89,123,97) | `#10180f` | **3.82**（盤の上）/ **3.3**（実画面） |
| 直したあと | `rgba(245,240,225,0.18)` | rgb(81,117,91) | `var(--cream)` | **4.56** |

再計測で**低コントラストは 0件**になった。

## 10. 改善提案（根拠付き）

### 10.1 被弾には「プロパティを取り合わない形」を1つ用意したい

今夜カンマで直せたのは3組で、**`card--hit` + `card--ultimate`（実測45件）だけが残った**。
`cardUltimate` が `transform` と `filter` の両方を使うためである。

擬似要素も空いていない。`::before` は絶技（9.4.10）と弱点（9.4.11）、
`::after` は毒（9.4.7）が使っている。**被弾だけ、どこにも逃げ場が無い。**

考えられるのは次の2つで、どちらも既存の演出に手を入れることになるため提案に留める。

- **(A) 被弾を `box-shadow` の赤い輪に作り替える。** `cardDrain` と同じ土俵になるので、
  hit + drained のときは今夜のカンマで両立する。ただし`.card--hit` の
  「揺れる」という手触りは失われる
- **(B) カードに専用の子要素を1つ増やす。** 擬似要素の取り合いから完全に降りられるが、
  手札まで含めた再描画のたびに要素が増える（B の夜の「DOM を増やしすぎない」に触れる）

**(A) を勧める。** 被弾は1試合に数十回起きるので、DOM を増やす代償のほうが重い。

### 10.2 総当たりの「起こりうる組」と、実測の「起きている組」は分けて見る

今夜、総当たりでは **29組**が消えると出たが、実際に同時に乗ったのは **8組**、
そのうち消えていたのは **4組**だけだった。
**総当たりの数字をそのまま報告していたら、7倍に盛った指摘になっていた。**

新しい演出を足したときは、総当たりで「ぶつかりうるか」を見たあと、
**必ず `renderBattle` を回して「実際にぶつかるか」を数える**ことにしたい
（今夜の手順をそのまま使える）。

### 10.3 「撮れた写真が別の画面だった」を検出する

今夜、結果画面のつもりで**次の対戦の配置フェーズ**を撮っていた。
「撮れなかった」は記録する決まりがあるが、**「別の画面が撮れた」は素通りする。**

撮影スクリプトに、画面ごとの**目印**（結果画面なら `h1.title` が
「勝ち！／負け…／引き分け」、対戦画面なら `.dock` がある、など）を持たせ、
合わなければ「撮れなかった」と記録するようにしたい。今夜の直しはこの形にしてある。

### 10.4 積み残しの古いもの

SPEC 16.5.2 の誤記は**15夜**、SPEC 8.3 の内訳列は4夜。
**夜間ジョブに「明らかな誤記の訂正だけは許す」枠を作るかどうか**を判断いただきたい
（09-20 から3夜続けて同じ提案をしている）。
