## 9. 改善提案（根拠付き）

### 9.1 関門の `BASE` の求め方を、基点の選び方とそろえる（今夜の当事者）

`BASE=$(git merge-base $ORIG_BRANCH <branch>)` は、**ブランチを `$ORIG_BRANCH` から生やしたとき**
にだけ分岐点を正しく返す。今夜のように `origin/main` から生やすと、`$ORIG_BRANCH` が main より
遅れているぶんだけ古い地点を指す。

規則の狙いは「**夜間ジョブ自身が**禁止されたものを触っていないか」なので、
**BASE は「STEP1 で選んだ基点そのもの」にするのが正しい。**

```sh
# STEP1 で基点を決めたときに、その場で控えておく
BASE=$(git rev-parse <STEP1 で選んだ基点>)   # origin/main か $ORIG_BRANCH のどちらか
```

09-17 の直し（`origin/main` → `merge-base`）は、**基点が作業ブランチのときだけ**正しかった。
今夜はその逆の側で同じ穴を踏んだことになる。

### 9.2 対話セッションの作業ブランチが main から遅れている

作業ブランチ `claude/darjeeling564-game-company-clone-7wo4zr` は `0abe7f8`（09-18 のマージ）を
含んでおらず、09-18 の演出（SPEC 9.3.3）が載っていない。**夜間ジョブは $ORIG_BRANCH を
書き換えない決まりなので触っていない。** 昼の作業でイラストを足すときに、
先に main を取り込んでおくと 9.1 の問題も自然に消える。

### 9.3 `nightly/2026-09-13` の u017 / u018 の扱いを決める（5.2）

次に絶技を作る A の夜に、`u017` から採るか、`u017` / `u018` を欠番にするかを決めておきたい。
**IDの衝突そのものは起きない**（09-13 のブランチはマージされない）が、
「欠番がある」のか「同じIDの別カードが2つある」のかは、後から見て分からなくなる。

### 9.4 SPEC 8.3 の「内訳」列の更新（5.1）
