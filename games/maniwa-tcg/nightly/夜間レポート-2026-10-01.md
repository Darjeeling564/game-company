## 10. 改善提案（根拠付き）

### 10.1 基点の判定 — 前夜の提案を自分で訂正する

09-30 に提案した判定は**不十分だった**。

```
# 09-30 の提案（今夜なら誤判定する）
git diff --numstat origin/main $ORIG_BRANCH | awk '$1!="-" && $1>0'
```

行が**変更**されているとき、古い版の行が「作業ブランチ側の追加」として数えられる。
今夜はこれで `sim.ts` に9行・`style.css` に1行が出たが、どちらも古い版だった。

**直した案。** 作業ブランチの**内容が main に含まれているか**を直接見る。

```
# 作業ブランチの木が、main のどれかの時点と一致するかを見る
git merge-base --is-ancestor $ORIG_BRANCH origin/main && echo "含まれている"
# スカッシュマージで祖先関係が切れている場合に備えて、内容でも見る
git diff --quiet origin/main $ORIG_BRANCH -- . && echo "内容も一致"
```

**いちばん確実なのは「作業ブランチに、main へまだ入っていない*変更*があるか」を
人が読める形で出すことである。** 次を勧める。

```
git log --oneline origin/main..$ORIG_BRANCH   # 空でなければ作業ブランチを基点に
```

スカッシュマージでは偽陽性が出るが、**偽陽性は「作業ブランチを基点にする」側に倒れる**。
今夜のように main が進んでいるときは差分の中身を人が確かめればよく、
**成果を落とす向きの誤りは起きない。** 規則の変更なので提案に留める。

### 10.2 関門 d4 を通すには `tools/ai.ts` を直す必要がある

8-2 のとおり、未使用の4枚はすべて **AI の評価**に由来する。

| 件 | 直し方の案 |
|---|---|
| リリース2体の姫神3体が出ない | 「2体を捨てて1体を出す」評価を、**盤の枠が余っているか**や**残りライフ**で変える。いまは打点だけで決めているように見える |
| `i010 双面の鏡` が出ない | 「相手を守備にする」は**自分が殴られない**ための札で、greedy は自分の打点しか見ていない。**受けの価値**を評価に入れる必要がある |

**これは待ち行列に無い作業である。** 第2段（カード追加）に進む前にやるか、
d4 を「第2段が終わってから有効にする」に後ろ倒しするか、**人に決めてほしい。**
