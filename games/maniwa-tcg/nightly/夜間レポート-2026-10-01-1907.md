## 9. ★ 関門 d4 で止めた。マージしていない

**6万戦のプール抽選で、115枚中5枚が一度も出なかった。**

```
★ s001 ユグドラシルEX     Lv7 攻2000
★ t003 ゼウスEX           Lv7 攻1600
★ d001 ニャルラトホテプEX Lv8 攻1900
★ i010 双面の鏡
★ i009 生贄の刃           ← 今夜足したカード
```

**5枚とも `tools/ai.ts` の評価に由来する。カードデータの問題ではない。**

- 上位3体は**2体生贄が必要なのに攻撃力が2000以下**。`score()` が場の打点の合計を
  見ているので、生贄に出す2体の打点を失う損のほうが大きく計算される
- `i010` は自分の与ダメージを下げるので評価が常に負になる
- **`i009` も同じ形である。** `lifeDamage self 200` + `draw 2` は、`score()` の
  数え方だと「手札 +2枚 = +240、ライフ −200、使った札 −120」で **−80**。
  **引いた札がこれから生む価値を `score()` が見ていない**ので、永久に選ばれない

### i009 を差し替えなかった理由

**差し替えれば d4 の未使用は4枚に減るが、それは「関門を通すための細工」である。**
夜間ジョブの取り決めが明示的に禁じている。しかも**4枚残るので関門は通らない。**

i009 は maniwa-tcg の `生贄の刃`（selfDamage 10 + draw 2）を素直に移したもので、
読み替えに無理はない。**自傷と引き換えに引くカードを避け続ければ、
カードプールのほうが歪む。**

**むしろ、同じ欠陥が5枚目を生んだことが、評価関数を直すべき根拠を1つ強くしている。**

### 関門は緩めていない。基準も書き換えていない

ブランチは push したまま残す。PR も作らない（d4 が落ちているため）。

6-3 のとおり、pool の「レアリティ別 平均勝率寄与」で UR は **+18.3pt** だが、

| 群 | 種類数 | 勝率寄与の範囲 |
|---|---|---|
| 絶技の UR | 33種 | +8.8 〜 +39.0pt |
| 神具・道標の UR | 8種 | **+3.0 〜 +9.8pt** |

絶技は対応姫神を積んだデッキにしか入らないので、**勝つデッキと相関する。**
新しい神具・道標を「UR の平均と比べて弱い」と判定すると、**必ず弱いと出る。**

**提案**: 夜間ジョブの STEP6.5-A にある「同レアリティの平均と比べる」を、
**「同レアリティ・同種別の平均と比べる」**に変える。
これは取り決めの変更なので、**この夜間ジョブでは実施していない。**

### 10.2 関門 d4 の扱いを決めてほしい（3つの案）

9章のとおり、d4 は `tools/ai.ts` の評価が直るまで落ち続ける。
人が「保留」と決めた以上、**今夜のジョブには解けない。**

| B | d4 を一旦外し、`tools/ai.ts` が直るまで「毎晩レポートに実測値を書く」扱いにする（d5 と同じ形） | 他の成果が毎晩マージできるようになる。**未使用の検出は失われない** |
| C | そのまま | 成果が毎晩たまり続ける。今夜のぶんが未マージ（前夜の PR #50 は人の判断でマージ済み） |

「AI が未完成のうちは関門にしない」にそのまま当てはまる。**

**関門の変更は提案に留める。自分では直さない。**

### 10.3 姫神戦記のカードを、姫神演義から機械的に生成する

5-2 のとおり、28枚中7枚で**系統・レアリティ・ルビ**が食い違っている。

```ts
// 案
export const SPELLS = [

  // from() が maniwa-tcg の ITEMS/ACTIONS/ULTIMATES から
  // name / ruby / origin / rarity を引いてくる

```
