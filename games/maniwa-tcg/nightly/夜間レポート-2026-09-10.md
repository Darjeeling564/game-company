## 7. 演出とビジュアル（STEP6.5-B）

### 7-1. 【最優先の宿題】入れ替えの演出が対戦中に出ることを確認した

09-08 は「CSS は当たるが、対戦中に一度も起こせなかった」で止まっていた。
**今夜、実際の対戦で出ることを確認した。**

#### 09-08 が起こせなかった本当の理由

演出の側ではなく、**確認用の自動操作の側に穴があった。**
準備フェーズで手札の**先頭だけ**を叩き続けていたため、先頭が場に置けない札
（神具・道標）だと「タップ → 何も選べない小窓 → 閉じる」を延々と往復し、
ベンチが埋まらないまま準備が終わらなかった。

```
i=0 modal=false hand=6   ← 先頭をタップ
i=1 modal=true  hand=6   ← 置けない札。小窓を閉じる
i=2 modal=false hand=6   ← また先頭をタップ…（30回繰り返して失敗）
```

手札を**全部順に試す**ようにしたところ、**1戦目の11手目で出た。**

#### 出たことの証拠

取りこぼさないよう、ポーリングではなく MutationObserver でクラスの出現を拾い、
出た 60ms 後に `animation-play-state: paused` を当てて画面を固めた。

```
名前          クラス                                       アニメ        変形                        不透明度
ギビル        card card--board card--active card--swap-in  swapInUp      scale 0.876 / translateY +18px  0.52
ガルダ        card card--board card--swap-out              swapOutDown   scale 1.203 / translateY −20px  0.45
```

親要素も期待どおり（迫り上がる側は `slots--active`、下がる側は `slots`）で、
**向きも自分側の規定（下から）に合っている。**

| 撮った時刻 | ファイル | 見えるもの |
|---|---|---|
| +60ms | `fx-swap-60ms.png` | 薄いまま、ベンチの大きさから立ち上がりはじめ |
| +180ms | `fx-swap-180ms.png` | ほぼ不透明。下がった側がベンチに収まりつつある |
| +320ms | `fx-swap-320ms.png` | 収まり際 |

**09-08 の「⚠ 画面での確認が半分しか取れていない」は解消した。**
今夜の3件の変更を入れたあと、もう2回（39手目・11手目）再現している。

### 7-2. 【新規・重い】盤面がスクロールで届いていなかった（SPEC 9.3.2 を追記）

SPEC 9.3.1 は「盤面は多少切れてもスクロールで届く」を前提にしている。
**390×844 で測ったところ、その前提が成り立っていなかった。**

| 項目 | 実測 |
|---|---|
| `.field` の見えている高さ | 593px |
| `.field` の中身の高さ | 828px |
| **画面の外にある量** | **235px** |
| その中にあるもの | **自分のベンチ（102px）**・ヒント・ログ |

`document.elementFromPoint` で自分のベンチの中心を叩くと、返ってくるのは
**ベンチではなくエネルギー帯**だった。つまり**最初の表示では一度も見えない。**

下までスクロールすれば見える。**しかし1手ごとに 0 へ戻っていた。**

```
スクロール前 = {top: 0,   max: 217}
下まで下げる = {top: 217}            ← ベンチが見える
ターンを渡す = {top: 0}    ← ★ 巻き戻る
```

`renderBattle` は毎回 `root.replaceChildren()` で作り直すので、
`scrollTop` が失われていた。**「スクロールで届く」状態ではなかった。**

#### 直したこと

1. 描き直しの前に `.board > .field` の `scrollTop` を読み、描き直したあとに戻す
2. **下に続きがあるときだけ**盤面の下辺に手がかり（ぼかしと下向きの印）を出す。
   出しっぱなしは「一番下まで見ているのに、まだ下がある」と嘘をつくので、
   `field.scrollHeight - clientHeight - scrollTop > 8` のときだけクラスを付ける

直したあとの実測。

```
スクロール前 = {top: 0,   max: 224}
下まで下げる = {top: 224}
ターンを渡す = {top: 224}  ← 保たれた
```

`scroll-top.png`（手がかりが出ている）と `scroll-bottom.png`
（下まで見ると手がかりが消え、ベンチ・ヒント・ログが見える）が証拠。

#### 直していないこと

**235px はみ出すこと自体は残っている。** 無くすには姫神カードを1割以上
小さくする必要があり、**見た目の方針の判断が要る**ので提案に留める（提案2）。

### 7-4. デッキ編集の入力欄が 336×36px だった

### 7-5. 【提案に留める】手札が7枚を超えると 44px を割る

計測で、決着間際の手札（10〜11枚）に 44px 違反が 10〜15件、名前切れが
12〜16件出た。手札の枚数ごとに実測した。

| 手札 | カード幅 | 高さ | **隣に隠されずに触れる幅** | |

| 6枚 | 76.6px | 101px | 65.3px | |
| 7枚 | 66.9px | 88px | 56.0px | |

| 11枚 | 45.9px | 60px | **35.8px** | |
| 13枚 | 40.2px | 53px | **30.4px** | |

**390px の幅では、9枚以上を1列に並べて 44px を保つことは算数の上で不可能である**
（`枚数 × 幅 ≤ 382` なので 44px なら 8枚まで）。

ただし**どれくらい起きるのかも測った。** 4,000戦・5,657ターンぶんの
「ターン終了時点の自分の手札」の分布。

```
  0枚 1.04% / 1枚 7.46% / 2枚 19.62% / 3枚 23.99% / 4枚 19.89%
  5枚 17.18% / 6枚 10.71% / 7枚 0.11%      最大 7枚
  9枚以上のターン: 0.00%
```

**AI の打ち回しでは9枚に届かない。** 支援カードを抱え込む人が遊べば届く。

直し方は3つあり、どれも見た目か手触りを変える。**独断で選ばない。**

| 案 | 内容 | 代償 |
|---|---|---|
| A | 手札を横スクロールにする | 扇の持ち上がりと影が縦に切れる（実測で縦に32pxはみ出す）。手札の段が 60px → 125px に伸びる |
| B | 手札を2段にする | 操作段が伸びるぶん盤面が縮む。盤面は既に 235px 足りない（7-2） |
| C | 何もしない | 9枚以上のときだけ 44px を割る。AI 対戦では 0.00% |
