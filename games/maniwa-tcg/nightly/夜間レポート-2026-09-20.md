### 7-2. 絶技の一回転が**一度も画面に出ていなかった**（今夜いちばん大きい発見）

溜めを作ろうとして `.card--ultimate` を張り込んだところ、**何試合回しても一度も捕まらない**。
調べたら、演出が出ていなかった。

`view.ts` の `lastUltimate` は **ログの末尾だけ**を見ていた。

```ts
/** 直前の1手が絶技だったか。ログの末尾だけを見る */
function lastUltimate(state: GameState): PlayerId | null {
  const last = state.log.at(-1)
  return last !== undefined && last.kind === 'ultimate' ? last.player : null
}
```

しかし **`ultimate` のログのあとには、必ずダメージ・気絶・手番終了が続く。**
2000試合で数えた。

```
2000試合。絶技が撃たれた回数: 1756
そのうち 撃った直後のログ末尾が 'ultimate' だった回数: 0 (0.0%)
撃った直後のログ末尾の種別:  ko 816 / end 632 / beginTurn 308
```

**1756回撃たれて、条件が成立したのは0回。** つまり SPEC 9.4.4 の一回転は、
書かれてはいたが**一度も画面に出たことがない**。

皮肉なことに、**すぐ上の関数のコメントに答えが書いてあった。**

> 攻撃のログは末尾に残らない（`attack` のあとに `damage` や `ko` が続く）ので、
> **`lastUltimate` のように末尾だけを見る方法では取れない。差分を見る。**

`lastAttacker` は同じ理由で差分を見る作りになっているのに、
**`lastUltimate` だけが末尾方式のまま取り残されていた。**

#### 直したもの

`lastAttacker` と同じ形にそろえた（`src/game/view.ts`）。

```ts
function lastUltimate(fresh: readonly LogEntry[]): PlayerId | null {
  let who: PlayerId | null = null
  for (const entry of fresh) {
    if (entry.kind === 'ultimate') who = entry.player
  }
  return who
}
```

**一回転そのものは1フレームも変えていない。** 出す条件だけを直した。

#### 競合を確かめた

一回転が出るようになると、同じカードに乗りうる他の演出と `animation` が競合する
（同じ詳細度は後勝ちで丸ごと置き換わる）。`style.css` の定義順は次のとおり。

| 行 | クラス |
|---|---|
| 1550 | `.card--hit` |
| 1802 | `.card--charged` |
| 1827 | `.card--drained` |
| **1838** | **`.card--ultimate`** |

**一回転がいちばん後ろなので勝つ。** SPEC 9.4.4 が
「絶技のときは踏み込み（`.card--lunge`）を付けない。一回転を残す」と決めているのと同じ向きである。

唯一の影響は `u005 神威の雷`（反動20）で、撃った本人の被弾の揺れが一回転に置き換わる。

### 7-3. 絶技の溜めを作った（没入感の題目「カードの動き」）

| 時間 | 見せるもの |
|---|---|
| 0〜26% | **溜め**。外から内へ光が集まり、カードの縁に収束する |
| 26〜70% | **放出**。集まった光が外へ開いて消える |

**守ったこと。**

- **一回転（`.card--ultimate`）の `animation` を書き換えていない。** 擬似要素に別の `animation` を置いた
- **`::after` を使っていない。** 毒（9.4.7）が `.card--envenom::after` を使っており、
  毒を受けた姫神が絶技を撃つと片方が消える。`::before` は空いていた

#### 色は2度やり直した（写真で沈んでいた）

**もり `#3f7452` とやみ `#4a3a5c` は依然として沈む**。

最終的に**2層**にした。内側にクリームの芯（`rgba(245, 240, 225, .95)`）を置いて
森緑の上で必ず読めるようにし、**外側だけを `--card-type` で色づける**。
専用の配色表は作っていない。

#### 光らせる時点も直した

擬似要素はカードの子なので、一回転の `rotateY` を一緒に受ける。
最初は山を 40% に置いたが、**その時点では板が横を向いていて、実機の写真で halo がほとんど読めなかった**。
25% 時点の傾きは -24度なので、**山を 26% に前倒しして出し切る**ようにした。

## 11. 改善提案（根拠付き）

### 11.1 計測スクリプトは `offsetWidth` で測る

今夜、同じ計測を**3度やり直している**。原因は2つとも計測側にあった。

1. `getBoundingClientRect()` は **`transform` を含む**。手札は扇状に回っている
   （`--fan-angle`）ので、**回転したカードほど大きく出る**。6枚の手札で「5×81px」という
   ありえない値が出たのも、アニメーション中の `scale` を拾ったためである
2. 複製でカードを増やすと、**枚数で切り替わるクラス（`.hand--dense`）が付かない**

`nightly/` の計測スクリプトは使い捨てなので残らないが、**この2点は毎回踏む**。
B の夜の手順に「レイアウトの大きさは `offsetWidth` / `offsetHeight` で測る。
`getBoundingClientRect()` は回転と拡大を含むので、タップ領域の判定には使わない」を
足しておきたい。

### 11.2 `LogEntry.kind` を条件に使うところは、必ず差分で見る

7-2 の `lastUltimate` は、**同じ間違いが他にもありうる形**をしている。
`state.log.at(-1)` で種別を判定している箇所は、**その種別のあとに別のログが続かない場合にしか成立しない**。

今夜の時点で `at(-1)` を使っているのはここだけだったが、
`core` が新しいログ種別を足したときに同じ罠を踏む。
SPEC 9.4 に「**ログ種別を条件にする演出は `freshLog` の差分から取る。末尾は見ない**」を
一文足しておきたい（既存節の書き換えになるので今夜は入れていない）。
