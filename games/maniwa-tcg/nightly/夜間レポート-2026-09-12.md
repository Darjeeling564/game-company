### 7-2. 【3夜ぶん積み残し】core の「クリーチャー」を画面側で「姫神」に訳した

`core/reduce.ts:95` が返す `'クリーチャーを1枚以上入れる'` が、デッキ編集にそのまま出ていた。

**core は触っていない**（CLAUDE.md 3章。決定論に関わる）。`src/game/main.ts` に訳の表を置き、
**出すところで訳す**（SPEC 9.10.1 として追記）。

```ts
const CORE_WORDS: readonly (readonly [string, string])[] = [
  ['クリーチャー', '姫神'],
]
function localizeCoreText(text: string): string {
  return CORE_WORDS.reduce((out, [from, to]) => out.split(from).join(to), text)
}
```

**表に無い語はそのまま出す。** 訳せないものを黙って消すと、何が足りないのか分からない
デッキが作れてしまうため。

### 7-3. 【新しい演出】毒になった瞬間を見せる（SPEC 9.4.7）

気絶（9.4.3）・攻撃（9.4.4）・入れ替え（9.4.5）には演出が入っていたが、
**状態異常だけが取り残されていた。** 毒は `card__status` の小さな「毒」札で表すだけで、
付いた瞬間には何も動かない。音（9.6 の `status`）は鳴るが、**目では分からない。**

SPEC 9.4.7 を先に追記してから実装した。

| 対象 | 決まり |
|---|---|
| 毒が**新しく付いた**個体 | 紫の膜がひと呼吸かかって消える（`.card--envenom`） |
| すでに毒の個体 | **何もしない**（付いた瞬間との区別がつかなくなる） |
| 「毒」の札 | 同時にひと回り大きくなってから戻る |

判定は気絶・入れ替えと同じ**差分方式**。`prevPoisoned` を持ち回り、
前回に毒でなく今回に毒なら「付いた瞬間」とする。

#### ⚠ transform を取り合わないよう、カード自身は動かしていない

`.card--hit`（被弾）・`.card--lunge`（踏み込み）・`.card--ultimate`（一回転）は
同じカードに乗りうる。**同じ詳細度の `animation` は後勝ちで丸ごと置き換わる**ので、
カード本体の `transform` を動かすと、どちらか片方しか出なくなる。

**毒と被弾は同じワザで同時に起きる**（a006 祟りの札 は damage + applyStatus）。
そこで **擬似要素の `opacity` と「毒」札の拡大だけ**で見せることにした。

色は `theme.ts` から引いていない。**毒は属性でも系統でもレアリティでもない**ので、
既存の配色表に対応する値が無い。この演出だけの紫を1つ置いた（専用の配色表は作らない）。

`prefers-reduced-motion: reduce` では膜を出さない。**そのときも「毒」の札は残る**ので、
情報は失われない。

#### 毒はどれくらい起きるのか（測った）

出ないのが仕組みの不具合なのか、自動操作が毒に届いていないだけなのかを分けるため、
core で 400戦を回して数えた（基準デッキ・greedy 同士）。

```
400戦のうち毒が1回でも起きた試合: 204 (51.0%)
毒の発生回数の合計: 284 / 1試合あたり 0.71
毒が初めて起きたターンの中央値: 5
```

**毒は半分の試合で起きる。** つまり演出が出ないのは確率の問題ではない。

#### 切り分けた — 演出の不具合ではない

画面のログに出る「毒になった」の回数と、`.card--envenom` の出現回数を
**同時に数える**版を作って回した。結果は次のとおり。

```
deck 5 試合1 終了 — ログの毒 0 回 / 演出 0 回
```

**両方とも0である。** つまりその試合では**毒が一度も起きていない**。
演出は「出すものが無かった」だけで、**仕組みが動かなかったわけではない。**

（ログの毒が1回以上あるのに演出が0回なら、演出の側の不具合と言い切れる。
今回はそうではなかった。）

原因は**自動操作の弱さ**である。今夜の操作は「手札の先頭を出す／ワザは最後の
選択肢」という単純なもので、**毒が初めて起きる中央値の5ターン目より前に
決着してしまう。** 8デッキ × 複数試合を3通りの組み方で回したが、
`.card--envenom` の出現を1度も捉えられなかった。

## 8. 今夜の計測で出たもの

### 8-1. 【新規・根拠あり】09-08 の修正に副作用がある

9画面の計測で名前切れが3件出たので、`.card__name` の寸法を全部測った。

| 場所 | 名前 | 箱の幅 | **使える幅** | padding-right | clamp | 必要行 |
|---|---|---|---|---|---|---|
| ベンチ | タオテツ | 49px | **30px** | 19px | 3 | 2 |
| ベンチ | ガルダ | 59px | **40px** | 19px | 3 | 1 |
| バトル場 | ペガソス | 85px | 66px | 19px | 2 | 1 |
| 手札 | 星辰の羅針 | 73px | **54px** | 19px | 2 | 2 |

**`padding-right: 19px` が全部の行から19px を削っている。**

09-08 は「1行目がバッジと重なるぶんだけ `padding-right` で逃がす」と書いたが、
CSS の `padding-right` は**箱全体**に効く。バッジは1行目の右上にしか無いのに、
2行目以降も同じだけ削られている。**ベンチでは箱の 39% が失われている。**

これが 8-battle の「スフィンクス」（必要4行・表示3行）と
8b-finish の「ヘパイストス」「カグツチEX」（必要2行・表示…実測では収まっていたが
手札が混むと切れる）の原因である。

#### 今夜は直していない

1行目だけを避ける正攻法は `float` + `shape-outside` だが、
**`float` こそが 09-08 に直した元のバグの原因**である（`.card__name` は行数を切るために
`display: -webkit-box` を使っており、これは整形文脈を作るので浮動要素を避けて箱ごと縮む）。

直すなら **`-webkit-line-clamp` をやめて `max-height` + `overflow: hidden` に変える**
必要があり、省略記号（…）の出方も変わる。**1晩で戻せる規模ではない**ので提案に留める。
