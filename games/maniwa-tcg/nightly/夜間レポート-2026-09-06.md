### 7-1. 撮影の前提 — **DotGothic16 が読み込めていない**

先に断っておく。**今夜のスクリーンショットは、指定フォントが当たっていない状態のものである。**

```
document.fonts        → []（空）
失敗したリクエスト     → net::ERR_CONNECTION_RESET
                        https://fonts.googleapis.com/css2?family=DotGothic16&display=swap
body の font-family   → "DotGothic16, system-ui, sans-serif"
```

この環境から Google Fonts に到達できないため、全画面が **fallback の `system-ui`** で描かれている。
したがって**文字の形・字幅に関する指摘は今夜は行わない**（行っても実機と一致しない）。
以下の指摘は、フォントに依存しない項目（寸法・色・重なり・語彙）に絞ってある。

**これは実装の欠陥ではないが、CLAUDE.md 9章「DotGothic16 のセルフホスト化」の根拠にはなる。**
`display=swap` を指定しているので、CDN に届かない端末では**警告も出ずに別の書体で表示される**。
機内モードや CDN 遮断下の初回起動がこれに当たる。優先度は低いが、事象として記録しておく。

### 7-5. 新しい演出の提案

#### 提案1: 気絶（KO）の演出 — **推す**

**どの画面のどの瞬間か**: 対戦画面で、姫神の HP が 0 になってバトル場から消える瞬間。

**なぜ必要か**: このゲームで最も重要な出来事は KO である。3ポイント先取が勝利条件で、
ポイントは KO でしか動かない。それなのに**今は KO 専用の演出が1つも無い**。
既存のキーフレームは18個あるが、被弾（`cardHit`）・ドロー（`cardDraw`）・配置（`cardPlace`）・
ポイント点灯（`pipOn`）はあっても、**倒れたカード自身には何も起きない**。次の描画で黙って消える。

`pipOn` でポイントは光るが、それは画面上端のヘッダーである。プレイヤーが見ているのは
盤面中央なので、**視線の位置と光る位置がずれている**。

**実装の見積もり**: **`core` の変更は不要。** ログに `ko` が既にあり、ポイント数まで入っている。

```
games/maniwa-tcg/src/core/effects.ts    → 変更なし
games/maniwa-tcg/src/game/view.ts:149   → formatLogEntry が 'ko' を既に解釈している
```

`renderBattle` は `prevBoard` との差分で `placed`（増えた id）を出しているので、
**同じ仕組みで「消えた id」を取れば足りる**。ただし消えた要素は次の描画に存在しないため、
1描画ぶん残す必要がある。`view.ts` の `makeFx` 周辺に手が要る。CSS だけでは済まない。

- `style.css`: `@keyframes cardFaint`（傾いて沈み、色が抜ける）を1つ追加
- `view.ts`: 消えた instanceId を1描画ぶん保持して `.card--faint` を付ける。**20〜30行程度**
- `prefers-reduced-motion` のブロックに `.card--faint` を追加（既存の方針に合わせる）

**SPEC への追記案**（CLAUDE.md 7章に従い、実装より先に SPEC を書く）:

> ##### 9.4.3 気絶の演出
>
> 姫神の HP が 0 になってバトル場から消えるとき、消える前に **0.45 秒**の演出を挟む。
> カードを手前に傾けながら不透明度を落とし、彩度を 0 に近づける。
>
> 気絶はポイントが動く唯一の出来事であり（SPEC 3.2）、盤面の中央で起きる。
> ヘッダーのポイント点灯（`pipOn`）だけでは視線の位置と合わないため、
> **倒れたカード自身にも演出を置く**。
>
> `prefers-reduced-motion: reduce` のときは演出を行わず、即座に消す。

#### 提案2: 弱点ヒットの表示 — **見送りを推す**

**どの画面のどの瞬間か**: 攻撃が弱点を突いて +20 された瞬間。

**なぜ必要か**: 弱点は SPEC 17.4 の相性表で決まり、カード詳細には「弱点 水（+20）」と
出ている。しかし**攻撃したときに弱点が乗ったかどうかは画面に出ない**。
70ダメージのワザが 90 通ったとき、プレイヤーには理由が分からない。

**実装の見積もり**: **`core` の変更が要る。** ダメージのログは加算後の合計しか持っていない。

```
games/maniwa-tcg/src/core/effects.ts:78
  return log(..., 'damage', `#${slot.instanceId} +${amount}`)   ← bonus が消えている
```

`amount` は `base + bonus` の結果で、内訳が残らない。表示するには detail に bonus を
足す必要があり、**core の出力が変わる = 決定論リプレイのハッシュが変わる**。
テストの期待値の作り直しが要る。

**費用に対して得るものが小さいので、今夜は見送りを推す。**
