#### (1) 弱点に当たった瞬間を見せる（SPEC 9.4.11・新規）

**弱点は、当たった瞬間だけ画面に出ていなかった。**
相性は `WEAKNESS_CHART` から引かれ、バトル場への攻撃にだけ上乗せが乗る（SPEC 3.4 / 17.4）。
ところが画面では**長押しでカード詳細を開いたときにしか「弱点 ◯◯（+40）」が読めない。**
対戦中は HP の減り方が変わるだけで、ダメージのログ（`#12 +90`）にも上乗せ込みの数しか
出ないので、**なぜ大きく減ったのかを知る手がかりが画面に無かった。**

これは STEP6.5-B の題目の「状態の伝達 — 弱点ヒットなど、『何が起きたか』が
数字を読まないと分からない場面」そのものである（毒 9.4.7・ポイント 9.4.8・
エネルギーの剥がし 9.4.9 は済み、弱点だけが残っていた）。

**判定は `core` を変えずに描画側で行った。** `WEAKNESS_CHART` と `weaknessBonus` は
すでに `view.ts` が詳細画面で使っている。`core` にログを足せば済む話だが、
出力が変わると決定論リプレイのハッシュが動く（CLAUDE.md 3章）ので触っていない。

変更したファイル。

| ファイル | 変更 |
|---|---|
| `src/game/view.ts` | `Fx.weak: ReadonlyMap<number, EnergyType>` を追加。`makeWeak()` を新設し、`creatureCard` で `.card--weak` と `--weak-type` を付ける |
| `src/game/style.css` | `.card--weak::before` と `@keyframes weakStrike`、および `prefers-reduced-motion` の静止形 |

```ts
function makeWeak(
  state: GameState,
  lunge: PlayerId | null,
  striker: Creature | null,
  hit: ReadonlyMap<number, number>,
): ReadonlyMap<number, EnergyType> {
  const weak = new Map<number, EnergyType>()
  if (lunge === null || striker === null) return weak
  const defender = state.players[opponentOf(lunge)].active
  if (defender === null || !hit.has(defender.instanceId)) return weak
  const strikerType = requireCreature(striker.cardId).type
  const defenderType = requireCreature(defender.cardId).type
  if (weaknessBonus(strikerType, defenderType) > 0) weak.set(defender.instanceId, strikerType)
  return weak
}
```

**ぶつからないことを確かめた。**

- **カード本体の `animation` も `transform` も使っていない。** 弱点のダメージは必ず
  被弾（`.card--hit`）と同時に起きるので、同じ詳細度で置くと後勝ちで揺れが丸ごと消える
  （毒 9.4.7・剥がし 9.4.9 で2度踏んでいる）
- **`::after` は使っていない。** 毒（`.card--envenom::after`）と同じカードに乗りうる
- **`::before` は `.card--ultimate`（9.4.10）が使っているが、ぶつからない。**
  上乗せは `slot.owner !== actor` のバトル場にしか乗らないので、
  撃った側と殴られた側が同じカードになることが無い（`core/effects.ts` で確認）
- 色は `theme.ts` の `TYPE_COLOR` から引いた。**専用の配色表は作っていない**

**実際に画面に出ることを確かめた。** 本番と同じ `renderBattle` を呼び、
core で試合を進めて1手ごとに描き直して数えた。

| 測った内容 | 結果 |
|---|---|
| 攻撃・絶技の手数 | 279 |
| 弱点の上乗せが乗った手数（core の規則から**独立に**計算） | **40** |
| そのうち `.card--weak` が付いた | **40 / 40** |
| 乗っていない手で付いてしまった（誤検出） | **0 / 239** |

実例（カグツチ〈炎〉→ フンババ〈森〉・上乗せ +20）のときのクラスは

**被弾の `.card--hit` と共存している**。`--weak-type` は `#c0392b`（炎）。

## 10. 改善提案（根拠付き）

### 10.1 `.card--hit` と `.card--drained` は現在ぶつかっている

今夜 `.card--weak` を置くにあたって既存の演出を読み直したところ、
**`.card--hit` と `.card--drained` は、どちらもカード本体に `animation` を
同じ詳細度で置いている**（`style.css`）。

```css
.card--hit     { animation: cardHit 0.42s ease-out; }
.card--drained { animation: cardDrain 0.5s ease-out; }
```

エネルギーを剥がすワザは**同時にダメージも与える**ので、両方が同じカードに乗る。
同じ詳細度の `animation` は後勝ちで丸ごと置き換わるため、
**後に書かれている `.card--drained` が勝ち、被弾の揺れが出ていない。**
`.card--drained` のすぐ上のコメントは、まさにその事故を避けるために
「カード本体の `transform` は動かさない」と書いているが、
`animation` プロパティ自体が競合することは防げていない。

直すなら `.card--drained` を擬似要素に移すことになるが、
**既存の演出の作り替えにあたる**ので今夜は手を付けていない。
`.card--weak` は初めからこの罠を避けて `::before` に置いた。
判断をいただきたい。

### 10.2 `end` のログにも音を足すかどうか

`end`（400件）には `SFX` の定義が無いが、`main.ts` が勝敗を見て
`win` / `lose` / `draw_game` を鳴らし分けているので、鳴らないわけではない。
ただし**ログ種別から引く仕組みの外にある例外**なので、
`sound.ts` を読んだだけでは「穴がある」ように見える。
`end` を定義して `main.ts` の鳴らし分けと二重にするのは音が濁るため、
**`sound.ts` のコメントに「`end` は UI 側で鳴らし分ける」と1行書く**のが良いと思う
（今夜は 9.6.4 の SPEC 側にだけ書いた）。

### 10.3 積み残しの古いもの

**夜間ジョブに「明らかな誤記の訂正だけは許す」枠を作るかどうか**を判断いただきたい
